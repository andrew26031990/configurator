# Выкладка патча безопасности

Порядок важен: сначала конфиг, потом код. Иначе сайт на минуту ляжет
с сообщением «Конфигурация не найдена».

## 1. Перед выкладкой — сменить секреты

Всё перечисленное лежало в репозитории открытым текстом и остаётся
в истории git. Пока не сменено — считается скомпрометированным.

- [ ] Пароль MySQL-пользователя `wp_user` (cPanel → MySQL Databases)
- [ ] Токены Telegram-ботов `1675277208:...` и `6232662696:...` (@BotFather → `/revoke`)
- [ ] Ключи reCAPTCHA (google.com/recaptcha/admin)
- [ ] Пароль почты `sale@pcmarket.uz` (лежал в закомментированном коде `mail.php`)
- [ ] Пароль админа конфигуратора — просто войти под ним один раз
      после выкладки, хеш автоматически переедет на bcrypt

## 2. Создать конфиг на сервере

`config.local.php` не в git — его надо создать на сервере руками:

```bash
cp config.local.example.php config.local.php
```

и вписать новые значения. Права: `chmod 640 config.local.php`.

## 3. Выложить код

Все файлы, кроме `config.local.php`.

## 4. Удалить с сервера то, чего там быть не должно

```bash
rm -f modules/db-backup-*.sql
rm -f modules/error_log modules/products/error_log
rm -f modules/addCategory.php modules/addTypes.php modules/removeCategory.php
rm -f modules/modals.php modules/admin/getProducts.php
rm -rf modules/Controllers
```

## 5. Залить `.htaccess` в каталог загрузок вручную

`configurator/images/` в `.gitignore`, поэтому файл не приедет с кодом.
Скопировать `configurator/images/.htaccess` по FTP — он запрещает
исполнение PHP в каталоге, куда админка кладёт картинки.

## 6. Проверить после выкладки

- [ ] Открывается https://configurator.pcmarket.uz/ — видны 3 категории
- [ ] `?cat=play-profy` — выбор компонента считает сумму, меняет картинку
- [ ] Клик по фильтру (Все / Z370 / …) перерисовывает список
- [ ] «Сохранить в PDF» отдаёт файл
- [ ] Ссылка на конфигурацию открывается с проставленными галочками
- [ ] Заявка «Купить» приходит в Telegram и появляется в `orders`
- [ ] Вход в админку работает, повторный вход тоже (проверка перехода на bcrypt)
- [ ] В админке: добавление и правка товара с картинкой, дерево категорий

## Важно про антивирус на хостинге

Windows Defender при разработке пометил `security.php` как
`Backdoor:PHP/Masqshell.E` — ложное срабатывание на связку
`imagecreatefromstring(file_get_contents(...))`, которая входит в
сигнатуры «шеллов, замаскированных под картинку». Код переписан на
типовые `imagecreatefromjpeg/png/gif`, срабатывание ушло.

Это стоит иметь в виду: ImunifyAV / ClamAV на cPanel используют похожие
сигнатуры, а `security.php` подключается из каждой точки входа — его
карантин уронил бы весь сайт. Если после выкладки сайт отдаёт 500,
первым делом смотреть карантин антивируса в панели хостинга.

## Что осталось незакрытым (сознательно)

- **CSRF-токенов нет.** Вместо них cookie сессии помечена `SameSite=Lax`,
  что закрывает CSRF на POST из чужого домена. Нормальные токены —
  в laravel-версии.
- **История git хранит старые секреты и дампы базы.** Чистка истории
  (`git filter-repo`) переписывает все коммиты; смена секретов из п.1
  решает проблему надёжнее.
- **Роли пользователей.** Пользователь по-прежнему один и без ролей.
- **Таблица `online`** (200k+ строк) не чистится; функция `on_line()`
  нигде не вызывается.
- **1291 висячая связь в `tree_prod`** и 4 в `tree_filter` — ссылаются на
  давно удалённые товары и фильтры.Следствие того, что старый
  `deleteProduct.php` удалял товар, не трогая связи. На витрину они не
  попадают (отсекаются JOIN-ом), поэтому чистку отложил до миграции
  структуры базы, где всё равно появятся внешние ключи.
- **Проверка `.htaccess`.** Встроенный сервер PHP её не читает, поэтому
  запрет на `settings.ini`, `config.local.php`, `*.sql` и `DEPLOY.md`
  проверяется только на Apache — пункты чек-листа выше.
- **Вход через форму логина целиком** не прогонялся: reCAPTCHA требует
  живых ключей Google. Проверены отдельно логика пароля (включая переезд
  на bcrypt) и работа админки под сессией.
